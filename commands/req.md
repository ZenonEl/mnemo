Используй навык **mnemo:work-state**.

**Завести:**
```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/mnemo_manifest.py req --export <dir> \
  --quote "<дословно, как было сказано>" --wanted-by "<кто хочет>" \
  --based-on "ctx:<slug>#iNNN" [--blocking "<что стоит без этого>"] [--stage "<этап>"]
```

**Завести пачкой** — когда из ТЗ снимается два десятка требований разом:
```
... req --export <dir> --batch trebovaniya.md --wanted-by "<кто>"          # план
... req --export <dir> --batch trebovaniya.md --wanted-by "<кто>" --apply  # запись
```
Файл — по требованию на строку; необязательный хвост после `::` задаёт ссылки
`based_on` для этой строки. Общие поля берутся из флагов один раз. Совпадающие
с уже заведёнными пропускаются, поэтому файл можно дополнять и прогонять снова.

`--blocking` в пакете общий и это честно: пачку правда останавливает одно и то
же. А вот **поля попытки — `--tried`, `--returned`, `--dead-end` — к пакету не
применяются**: они доказывают совершённое действие по конкретной записи, и одна
предъявленная попытка отправила бы наверх двадцать неподтверждённых блокеров.
Пакет заводит их со стороной «шаг наш» и говорит об этом вслух; чужой шаг
объявляется по одной, командой с `--id`.

**Обновить состояние:**
```
... req --export <dir> --id tNNN --state done --evidence "<коммит, скрин, прогон>"
```

**Заблокировано — предъяви попытку:**
```
... req --export <dir> --id tNNN --blocking "<что стоит>" \
  --tried "<что конкретно сделал>" --returned "<что вернулось дословно>" \
  --dead-end "<что должно измениться снаружи>"
```
Из трёх полей выводится `escalation`: заполнены все — `theirs` (ждём чужого
шага), нет — `ours` (следующий шаг наш). Незаполненная попытка запись не
отменяет, но команда скажет вслух, что завела как `ours` и какого поля не хватило.

**Проход самоопровержения** — после того, как сделал НОВУЮ попытку снять блокер:
```
... req --export <dir> --id tNNN --pass-outcome refuted --returned "<найденный обход>"
... req --export <dir> --id tNNN --pass-outcome confirmed --returned "<вторая улика>"
... req --export <dir> --id tNNN --pass-outcome insufficient
```
`confirmed` без пополнения `returned` команда сама переклассифицирует в
`insufficient`: подтверждение без новой улики не принимается.

## Что важно

**`--quote` дословно.** Требование — чужая воля, а не твой пересказ. Если
формулировка пришла из машинной расшифровки или конспекта, это видно по
достоверности материала в `--based-on`, и в цитате так и пиши.

**`done` и `verified` требуют `--evidence`.** «Сделано» без доказательства —
мнение, а не отчёт. Именно на этом разваливается ответ на вопрос «всё ли мы
сделали»: половина пунктов помечена сделанной, а чем — никто не помнит.

**`--blocking` — что стоит без этого.** Без него сводка возвращает сорок пунктов
вперемешку, и важное тонет. Заполняй, когда работа действительно упирается.

**Требование не редактируют — его отменяют новым.** Заказчик передумал: заводишь
новое с `--supersedes tNNN`. Старое остаётся читаемым, и видно, что от него
зависело.

**Расхождения — в `--note`.** «В протоколе написано одно, на скрине другое» это
не повод выбрать одно молча.
