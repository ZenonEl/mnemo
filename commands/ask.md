Используй навык **mnemo:work-state**.

**Завести** — четыре поля обязательны, команда откажется без них:
```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/mnemo_manifest.py ask --export <dir> \
  --text "<вопрос>" --impact "<что будет сделано иначе>" \
  --asked-of "<кто реально ответит>" --based-on "ctx:<slug>#iNNN" \
  --self-attempt "<чем сам пробовал закрыть и почему не закрылось>" \
  [--blocking "<что стоит без ответа>"]
```

Что проверить по каждому полю — в навыке, раздел «Заслон на вопросы». Коротко:
`--impact` называет, что изменится **в коде или конфигурации**, а не «будет
понятнее», и меняется при этом **наша** работа, а не чужая; `--asked-of` —
человек из реестра, который правда владеет ответом (если решаем сами — это не
вопрос); `--based-on` — материал, который ты открыл и в котором вопрос
действительно возник; `--self-attempt` — что искал, что прочитал, что
попробовал. «Изучал», «разбирался» команда отвергнет: это не попытка.

**Понизить до допущения** — вопрос не прошёл заслон, но выбрасывать его нельзя:
```
... ask --export <dir> --id qNNN \
  --assumed "<что приняли за верное>" --cost-if-wrong "<что переделывать, если нет>"
```
Это **не снятие**: `--dropped-reason` не ставится. Допущение уходит из списка
открытых и остаётся видимым в полной сводке отдельной секцией. Придёт настоящий
ответ — закрывай `--answered-by`, состояние станет `answered`.

**Блокер: предъявить попытку** — три поля, из которых выводится `escalation`:
```
... ask --export <dir> --id qNNN --blocking "<что стоит>" \
  --tried "<что сделал>" --returned "<что вернулось дословно>" \
  --dead-end "<что должно измениться снаружи>"
```
Не заполнил — запись всё равно заведётся, но как `ours` («следующий шаг наш»), и
команда скажет об этом вслух.

**Завести пачкой:**
```
... ask --export <dir> --batch voprosy.md --impact "<что меняется>" \
  --asked-of "<у кого>" --based-on "ctx:<slug>#iNNN" \
  --self-attempt "<чем сам пробовал закрыть>"            # план
... ask --export <dir> --batch voprosy.md --impact "<что меняется>" \
  --asked-of "<у кого>" --based-on "ctx:<slug>#iNNN" \
  --self-attempt "<чем сам пробовал закрыть>" --apply     # запись
```
Заслон действует и на пакет: двадцать вопросов без `--impact` — это двадцать
раз тот же мусор, а не исключение из правила. По вопросу на строку, хвост после
`::` — ссылки `based_on`. Отметки «спросили» / «отвечено», а также `--assumed`
и `--pass-outcome` к пакету не применяются: они про конкретный вопрос.

**Отметить, что спросили:**
```
... ask --export <dir> --id qNNN --raised-to "<кому>" --where "дейлик <репо>#110"
```

**Закрыть:**
```
... ask --export <dir> --id qNNN --answered-by "ctx:<slug>#iNNN"
```

## Что важно

**Вопрос закрывается ссылкой, а не словом.** `--answered-by` указывает на
материал, факт или требование, которое дало ответ. Голое «отвечено» — это
утверждение, которому нечем возразить; ссылку проверяет линтер.

**Состояние не хранится, а выводится**, в порядке `dropped` → `answered` →
`assumed` → `raised` → `open`. Поэтому оно не может разойтись с содержимым.
`assumed` стоит после `answered` намеренно: пришедший настоящий ответ обязан
перекрывать догадку, иначе её опровержение не видно.

**`--raised-to` обязательно отмечай, когда вопрос ушёл человеку.** Иначе
следующая сводка поднимет его заново как новый, и ты второй раз спросишь то, что
уже спрашивал. Отметки накапливаются: спросили дважды — две записи.

**`--impact` — что меняется от ответа.** Проверка простая: назови два исхода
ответа и для каждого — что конкретно будет сделано иначе. Оба ведут к тому же
коду — это не вопрос, а любопытство.

**Похожий вопрос команда покажет и откажется писать** без явного решения:
отметить существующий (`--id`), либо подтвердить, что это правда другое
(`--anyway`). Слить их сама она не вправе.

**Протухшее видно отдельно.** Вопрос, спрошенный больше недели назад без
ответа, попадает в секцию «ПРОТУХЛО» — его переспрашивают или снимают
(`--dropped-reason`), а не ждут дальше.
