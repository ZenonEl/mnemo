# Component: chat-sync

**Статус:** 📋 planned.

## Что делает
Синкает транскрипты диалогов с ассистентом между машинами **в зашифрованном
виде через git**, и даёт с ними работать: искать, удалять, форкать ветки
разговора.

## Зачем через git
- История версий из коробки, знакомый инструмент, работает поверх любого
  git-хостинга.
- Но: **в git уезжает только зашифрованный бандл, не открытый текст.** Диалоги —
  чувствительные данные, в репозиторий в чистом виде они не попадают.

## Модель
- Локально транскрипты лежат расшифрованными в приватном сторе (вне git).
- На синк — шифруются (`age`/`gpg`) в бандл `*.age`/`*.gpg`, коммитятся, пушатся.
- На другой машине — тянутся, расшифровываются ключом, кладутся в локальный стор.
- `.gitignore` пропускает в git **только** `*.age`/`*.gpg` (см. корневой gitignore).

## Операции над историей
- **search** — поиск по расшифрованным транскриптам (через core.retrieve).
- **delete** — удалить диалог/сообщение; синк удаления безопасно (в git — только
  шифртекст, ключ у владельца).
- **fork** — ответвить разговор от точки: новая ветка беседы, старая цела.

## Открытые вопросы
- Управление ключами: один симметричный ключ vs per-recipient (age keys).
- Гранулярность бандла: один архив vs по диалогам (влияет на diff/размер).
- Формат транскрипта: свой нормализованный JSON поверх исходных логов.
- Конфликты слияния зашифрованных бинарников (скорее replace-стратегия, не merge).
