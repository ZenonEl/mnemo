# Component: dailies

**Статус:** 📋 planned.

## Что делает
Подтягивает ежедневные рабочие логи (по дням и проектам) в общую память и
связывает их с остальным контекстом.

## Модель (внешняя система дейликов)
Дейлики живут как **issues** в отдельном репо: один issue = (дата, проект),
title `YYYY-MM-DD — <Project>`, project-лейбл + assignee. Тело = срез для
начальства (человеческий язык), комментарии = технический devlog.

mnemo этой системой **не владеет** — только читает и индексирует.

## Что делает коннектор
- Тянет issues (тело + комментарии) по фильтру проект/дата.
- Кладёт в RAW как `raw/dailies/YYYY-MM-DD_<project>.md` (дословно).
- В индекс: дата, проект, связанные issue/PR (кросс-реповые ссылки).
- Связка «дейлик ↔ контекст»: запрос «что делал по проекту X за неделю» →
  собирает дейлики + связанные материалы.

## Два регистра текста (важно, повторяет правило системы дейликов)
- **body для начальства** — живой язык, без AI-тэллов (прогон через
  humanizer). Обязательные значки-заголовки формата сохранять.
- **devlog (комментарии) — без humanizer**, обычный технический язык,
  детальный дамп. Это тот слой, который полезнее для ИИ-поиска.

При индексации различать эти регистры: для поиска ценнее devlog.

## Открытые вопросы
- Инкремент: как понимать, что в дейлике появился новый комментарий.
- Разделение контуров: рабочие дейлики — контур `work`, не смешивать с личным.
