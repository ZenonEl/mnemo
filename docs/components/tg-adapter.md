# Component: tg-adapter

**Статус:** 📋 planned.

## Что делает
Телеграм-бот как **единая дверь** к mnemo: поговорить с ассистентом, спросить
память, сгрепать инфу, отметиться в дейлике — с телефона, без терминала.

## Роль в архитектуре
Тонкий транспорт поверх ядра. Вся логика (поиск, ingest) — в core; бот только
принимает сообщения, зовёт core и красиво отдаёт ответ. Заменяем на CLI/MCP —
ядро не меняется.

## Сценарии
- `ask` — вопрос → `core.retrieve` → ответ **со ссылкой на RAW**.
- `grep` — точный текстовый поиск по стору.
- `ingest` — переслать боту сообщение/файл → уходит в RAW.
- `daily` — быстрая отметка в дейлик (утренний план / вечерний факт).
- `chat` — диалог с ассистентом с подмешанным контекстом из памяти.

## Дизайн
- Бот = адаптер, ассистент/поиск — за ядром. Бот не хранит состояние знания.
- Ответы всегда с источником: не «где-то было», а ссылка на item.
- Права: приватный бот на одного владельца (allowlist по user_id).
- Разделение контуров: команда сама указывает контур или он берётся из чата.

## Открытые вопросы
- Long-polling или webhook (webhook → нужен адрес; polling проще для local-first).
- Как отдавать длинные ответы (разбивка / файлом / ссылкой на summary).
- Аутентификация к ядру, если бот и ядро на разных машинах.
