# VISION — mnemo

_Рабочий документ. Пишу подробно, чтобы потом можно было сесть и делать по нему._

## Проблема

Контекст работы размазан по десятку мест: переписки в Telegram, issues на GitHub,
`.docx`/`.xlsx` от клиентов, логи прошлых диалогов с Claude, дейлики. Между собой
они не связаны. Найти «что мы решили по валюте в том проекте» = руками скроллить
чат + открывать доки + вспоминать, в какой ветке что. Знание есть, но оно не
доступно по запросу.

## Идея в одну фразу

**Единая личная память, в которую всё стекается в сыром виде, поверх строятся
пересказы и индекс, а сверху — поиск, к которому можно обратиться голосом бота,
из CLI или через MCP прямо из ассистента.**

## Три слоя (ядро концепции)

1. **RAW** — всё, что попадает в систему, сохраняется дословно, в оригинальном
   формате. Переписка — как есть, docx — сам файл + извлечённый текст + вшитые
   картинки, скрины — оригинал PNG. RAW неприкосновенен, на него ссылаемся «по
   факту». Производные данные (пересказы, эмбеддинги) — расходники, их всегда
   можно пересобрать из RAW.

2. **SUMMARIES / INDEX** — человекочитаемый слой поверх RAW: пересказы,
   хронология, участники, таблицы «фича → issue → статус». Чтобы за 30 секунд
   понять, что где лежит, без открытия сырых файлов.

3. **RETRIEVAL** — семантический поиск (вектора) + структурные фильтры (дата,
   проект, участник, источник). Возвращает ответ **со ссылкой на RAW** — не
   «где-то было», а конкретный файл/строка/сообщение.

## Прототип, который уже есть

Компонент **chat-export** уже обкатан вживую: переписка + вложения (2×docx с
извлечённым текстом и картинками) + скрины разложены в `raw/` + `summaries/` +
`INDEX.md` по схеме «дата_автор». Это доказательство, что схема «RAW +
пересказ + индекс» работает руками. Следующий шаг — автоматизировать её и
подключить остальные слои. Подробности — [`components/chat-export.md`](components/chat-export.md).

## Куда это растёт (полное видение)

- **Дейлики.** Подтягивать ежедневные рабочие логи (по дням/проектам) и связывать
  их с остальным контекстом: «покажи, что делал по проекту X за неделю».
  → [`components/dailies.md`](components/dailies.md)
- **TG-адаптер.** Телеграм-бот как единая точка входа: поговорить с ассистентом,
  спросить память, сгрепать инфу, отметиться в дейлике — не открывая терминал.
  → [`components/tg-adapter.md`](components/tg-adapter.md)
- **Синк чатов Claude.** Логи диалогов с ассистентом синкать между машинами
  **в зашифрованном виде через git**; с ними работать — искать, удалять,
  форкать ветки разговора. → [`components/chat-sync.md`](components/chat-sync.md)
- **Мозг (retrieval).** Векторная БД + оформление в **skill/MCP**, чтобы
  ассистент мог запрашивать всю память как инструмент.
  → [`components/retrieval.md`](components/retrieval.md)

## Принципы

- **RAW не теряется никогда.** Оригинал важнее любой обработки.
- **Local-first.** Работает на одной машине без сети. Синк — опция, и он
  шифрованный: в git уезжают только зашифрованные бандлы, не открытый текст.
- **Адаптеры, а не привязка.** TG/CLI/MCP — сменные «двери» к одному ядру.
  Ядро не знает, кто его дёргает.
- **Не стыдно показать.** Чистая структура, никаких секретов в репе, MIT.

## Чего mnemo НЕ делает

- Не заменяет рабочие трекеры (issues живут там, где живут; mnemo их читает и
  связывает, но не является их владельцем).
- Не хранит секреты/ключи в репозитории.
- Не смешивает разные контуры: рабочий контент и личные заметки разведены
  тегами/источниками, а не свалены в кучу.
