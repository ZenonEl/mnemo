# mnemo — skill-pack для стандарта чат-экспортов

**Дата:** 2026-07-27
**Статус:** согласовано, к реализации
**Репозиторий:** `github.com/ZenonEl/mnemo` (публичный, личный аккаунт — не org)

---

## 1. Цель

Зафиксировать **единый воспроизводимый стандарт чат-экспортов** и поставить его как
плагин Claude Code, который работает в любом проекте.

Задача, которую он решает: рабочий контекст (переписка с заказчиком, ТЗ в `.docx`,
скрины, голосовые, транскрипты созвонов) сейчас разбирается руками, каждый раз
чуть по-своему. Результат получается хороший, но невоспроизводимый: три сделанных
экспорта имеют три разные раскладки. Нужно, чтобы:

- добавление материала было командой, а не ручной работой;
- любой ответ по архиву вёл к конкретному оригиналу с указанием, насколько он дословен;
- архив можно было проверить линтером, а не глазами;
- следующая сессия Claude открывала `INDEX.md` и понимала ТЗ, не пересобирая контекст.

## 2. Не-цели

Явно вне скоупа этой итерации:

- векторный поиск, эмбеддинги, гибридный ранкинг;
- MCP-сервер;
- расшифровка голосовых;
- дейлики, TG-адаптер, chat-sync (это фазы 4–6 из `docs/ROADMAP.md`);
- владение issue-трекерами: mnemo их читает и ссылается, но не является их источником.

Всё перечисленное уходит в `BACKLOG.md` и ложится поверх стандарта позже без его
переписывания — при условии, что контракт `item` заложен верно сейчас.

## 3. Референсы (что обобщаем)

Три реальных экспорта, сделанных вручную. Они и будут приёмочными тестами.

| Экспорт | Что в нём ценного | Чего не хватает |
|---|---|---|
| `pervyy-export/chat_export/` | эталонная раскладка RAW+summaries+INDEX; извлечение текста и вшитых картинок из `.docx`; `conventions.md`; `findings-log.md` с секцией «распределено» | нет машиночитаемого слоя, INDEX не упоминает половину своих же файлов |
| `vtoroy-export/_chat-export/` | статусная таблица задач «от кого / кому / статус» | плоский `raw/`, нет `summaries/` |
| `174/ChatExport_2026-07-23/` | блок провенанса (дословно / конспект / невосстановимо); список вычищенного | всё в одном файле на 59 КБ |

Из них выведены пять артефактов, которых не было в исходной спеке `docs/components/chat-export.md`:
`conventions.md`, `findings-log.md`, `redactions.md`, модель достоверности, реестр хвостов.

## 4. Модель распространения

**Плагин Claude Code, ставится глобально, работает в текущем каталоге проекта.**

Публичная репа содержит **только** навыки, команды, скрипты и текст стандарта.
Данные в неё не попадают никогда — экспорты создаются рядом с проектом, к которому
относятся, и исключаются из его git.

Отвергнутые варианты:
- *репа как хранилище* — смешивает публичный инструмент и приватные клиентские данные в одном дереве;
- *централизованный стор сразу* — преждевременно; станет осмысленным, когда появится поиск (см. бэклог).

## 5. Раскладка репозитория

```
mnemo/
├── .claude-plugin/
│   └── plugin.json              манифест плагина
├── SPEC/                        ← СТАНДАРТ (SSOT)
│   ├── STANDARD.md              раскладка, контракт item, правила INDEX
│   ├── PROVENANCE.md            модель достоверности
│   ├── CHANGELOG.md             версии стандарта
│   └── LICENSE                  CC BY-SA 4.0
├── skills/
│   └── chat-export/
│       ├── SKILL.md             навык: то, что требует суждения
│       └── references/          шаблоны артефактов
├── commands/                    slash-команды (11 шт., см. §9)
├── scripts/                     детерминированное, Python 3 stdlib-only
│   ├── mnemo_manifest.py        чтение/запись MANIFEST.json, хеши
│   ├── mnemo_extract.py         распаковка docx/xlsx → текст + media
│   ├── mnemo_render.py          MANIFEST.json → INDEX.md
│   └── mnemo_verify.py          линтер стандарта
├── docs/                        VISION / ARCHITECTURE / ROADMAP / components
├── BACKLOG.md
├── README.md
└── LICENSE                      AGPL-3.0
```

### Архитектурные принципы

- **SSOT.** `SPEC/STANDARD.md` — единственный источник истины о формате. Внутри
  конкретного экспорта единственный источник истины о содержимом — `MANIFEST.json`.
  Всё остальное (`INDEX.md`, срезы, отчёты) — производные и пересобираемые.
- **Инверсия зависимостей.** Навыки и скрипты зависят от спеки; спека о них не знает.
  Будущий MCP-сервер или CLI станет ещё одним потребителем той же спеки, а не поводом
  её переписать.
- **Разделение ответственности.** Скрипты делают механическое и проверяемое
  (распаковать, посчитать хеш, слинтовать, отрендерить). Навык делает то, где нужно
  суждение (пересказ, оценка достоверности, что вырезать). Смешение сделало бы
  стандарт непроверяемым: линтер, написанный «на усмотрение модели», не линтер.
- **Одна команда — одна ответственность.** Три раздельные `add-*` вместо одной
  универсальной: они пишут в разные зоны RAW с несовместимыми правилами.
- **Без зависимостей.** Скрипты — только стандартная библиотека Python 3
  (`zipfile`, `xml.etree`, `hashlib`, `json`, `pathlib`). Причина: переносимость и
  работа на NixOS без возни с окружением.

## 6. Модель достоверности (провенанс)

Каждая единица хранения несёт `fidelity` — насколько она близка к оригиналу.

| Значение | Определение | Пример |
|---|---|---|
| `verbatim` | дословно из машинного источника, без пересказа | сообщения из `result.json` Telegram-экспорта |
| `reconstructed` | текст дословный, но добыт из вторичного источника | сообщения, восстановленные из jsonl-логов сессии |
| `digest` | конспект/пересказ, сделанный человеком или моделью | «рабочий конспект переписки» |
| `placeholder` | оригинала нет, есть только описание | недостающий PNG скриншота |

**Правила:**

1. Любая цитата из архива обязана сопровождаться `fidelity`.
2. `digest` **запрещено** приводить как прямую речь участника.
3. Любое значение кроме `verbatim` обязано иметь непустой `fidelity_note` с объяснением.
4. При сомнении выбирается более слабое значение (`digest`, а не `reconstructed`).

Обоснование: архив создаётся для приёмки и передачи работы. Ошибка «модель приписала
заказчику слова из моего же конспекта» дороже любой другой в этой системе.

## 7. Контракт `item`

```yaml
item:
  id: i<NNN>                      # i001, i002, … стабильный, не переиспользуется
  source: telegram | docx | xlsx | screenshot | voice | claude-chat | daily | web | other
  origin: <string>                # откуда физически взято: "result.json:1373", "прислано в чат 21.07", "кэш сессии"
  fidelity: verbatim | reconstructed | digest | placeholder
  fidelity_note: <string|null>    # обязателен, если fidelity != verbatim
  date: YYYY-MM-DD                # дата материала, не дата импорта
  imported: YYYY-MM-DD            # дата попадания в архив
  participants: [<string>, ...]
  raw_path: <path|null>           # относительный путь от корня экспорта; null только при status=unrecoverable
  sha256: <string|null>           # хеш файла по raw_path; null при status != present
  derived_paths: [<path>, ...]    # производные от этого же материала (см. ниже)
  status: present | missing | unrecoverable
  summary_ref: <path|null>
  redactions: [<redaction_id>, ...]
  tags: [<string>, ...]
  project: <slug|null>
  contour: work | personal | public
```

Пояснения к полям, где возможно двойное чтение:

- `id` — простой возрастающий счётчик, а не ULID: скрипты обязаны работать на голой
  стандартной библиотеке (§5), а ULID в неё не входит. Сортируемости по `date` достаточно.
- `date` vs `imported` — разделены намеренно: материал от 13.07 может попасть в архив 23.07,
  и хронология должна строиться по первому.
- `status: missing` — оригинал существует в природе, но не добыт (можно достать позже).
  `status: unrecoverable` — оригинал утрачен принципиально (голосовое не сохранено,
  временный кэш стёрт). Различие нужно `gaps`: первое — задача, второе — факт.
- `raw_path` при `status: missing` указывает на **ожидаемый** путь, файла там ещё нет.
  Это позволяет положить файл позже, не меняя запись.
- `derived_paths` — то, что извлечено из этого материала автоматически:
  `_extracted-text/<...>.txt` и `from-docx/<doc>/imageN.png`. Своих `item` они не
  получают: у них та же достоверность и то же происхождение, что у родителя, а
  отдельные записи только раздували бы манифест. Линтер знает о них и не считает
  сиротами (V03). Они пересобираемы: удалил → `add-files` на том же оригинале восстановит.
- `contour: public` — материал, разрешённый к публикации; используется командой `publish`.

## 8. Состав экспорта

```
<export>/
├── INDEX.md                      производный, генерируется
├── MANIFEST.json                 SSOT содержимого
├── summaries/
│   ├── <YYYY-MM-DD>_chat-summary.md
│   ├── attachments-summary.md
│   ├── conventions.md
│   ├── findings-log.md
│   └── redactions.md             производный, генерируется
└── raw/
    ├── messages/     YYYY-MM-DD_<author>.md
    ├── attachments/  <оригиналы> + _extracted-text/
    ├── screenshots/  <оригиналы> + from-docx/<doc>/
    └── voice/        <оригиналы или заглушки>
```

### Схема `MANIFEST.json`

```json
{
  "mnemo_spec": "1.0",
  "export": {
    "slug": "email-china",
    "title": "Приёмка и передача проекта pervyy-export",
    "created": "2026-07-27",
    "contour": "work",
    "project": "pervyy-export",
    "participants": ["Пётр Иванов", "ZenonEl"]
  },
  "items": [ /* см. §7 */ ],
  "redactions": [
    {
      "id": "r001",
      "reason": "pii | off-topic | leaked-internal | client-confidential",
      "description": "паспортные данные директора",
      "scope": "raw/attachments/armada-passport.pdf",
      "reversible": true,
      "vault_ref": "<путь вне архива|null>"
    }
  ]
}
```

`redactions` вынесены на верхний уровень, а не внутрь `item`: одна редакция может
затрагивать несколько единиц, и у неё своё основание, не привязанное к файлу.

### Что генерируется, а что пишется

| Файл | Кто пишет | Пересобирается |
|---|---|---|
| `MANIFEST.json` | команды `add-*`, `init`, `redact` | нет — это источник |
| `INDEX.md` | `scripts/mnemo_render.py` из манифеста | да, `/mnemo:sync` |
| `summaries/redactions.md` | `mnemo_render.py` из манифеста | да, `/mnemo:sync` |
| `*_chat-summary.md`, `attachments-summary.md` | навык (LLM) | да, по запросу |
| `conventions.md`, `findings-log.md` | навык + команды `rule` / `note` | нет — накапливаются |

Ключевое отличие от текущей ручной практики: `INDEX.md` перестаёт быть рукописным.
Сейчас он расходится с содержимым молча — в `pervyy-export` индекс не упоминает
`conventions.md` и `findings-log.md`, хотя они рядом. Один источник + генератор
делает такой дрейф невозможным.

### `findings-log.md` — жизненный цикл

Артефакт с состоянием, а не просто заметки. Каждая запись имеет статус:

- `open` — факт зафиксирован, никуда не отправлен;
- `distributed` — уехал в WORKLOG / issue / дейлик, с указанием куда и каким коммитом;
- `dropped` — оказался неверным или неактуальным, с причиной.

Это формализация того, что уже делалось вручную (секция «✅ РАСПРЕДЕЛЕНО» с хэшами
коммитов). Секция «пока ничего не пушим» становится состоянием, а не припиской.

## 9. Команды

Все под неймспейсом плагина: `/mnemo:<команда>`.

| Команда | Вход | Что делает |
|---|---|---|
| `init` | `[--slug]` | создаёт экспорт **или принимает существующий** (§10) |
| `add-text` | текст или путь | → `raw/messages/YYYY-MM-DD_<author>.md`; спрашивает автора, дату, `fidelity` |
| `add-files` | пути | → `raw/attachments/`; для docx/xlsx извлекает текст в `_extracted-text/` и вшитые изображения в `raw/screenshots/from-docx/<doc>/` |
| `add-screens` | пути | → `raw/screenshots/`, копия байт-в-байт, без пересжатия |
| `note` | текст | запись в `findings-log.md` со статусом `open` |
| `rule` | текст | запись в `conventions.md` с источником (кто, когда сказал) |
| `redact` | цель + причина | регистрирует редакцию, при `reversible` кладёт оригинал в хранилище вне архива |
| `sync` | — | пересобирает `INDEX.md` и `redactions.md`, обновляет хеши |
| `verify` | — | линтер (§11) |
| `gaps` | — | реестр хвостов: `status != present`, `fidelity: placeholder`, незакрытые TODO |
| `publish` | `[--out]` | публичный срез: структура, стандарт, `conventions.md`, только `contour: public` |

Все мутирующие команды после работы вызывают `sync`, затем `verify`, и сообщают результат.
Порядок важен: `sync` пересобирает только детерминированные производные (`INDEX.md`,
`redactions.md`), поэтому дёшев и безопасен на каждой мутации. LLM-пересказы он не
трогает — их перегенерация всегда запрашивается явно. Без авто-`sync` предупреждение
`V08` висело бы после каждой команды и обесценило бы линтер.

## 10. `init` с приёмкой существующего

Приёмка встроена в `init`, а не вынесена отдельной командой: иначе чистый `init`
можно случайно запустить поверх готового экспорта и затереть его.

**Алгоритм:**

1. Сканирует текущий каталог на признаки существующего экспорта:
   `chat_export/`, `_chat-export/`, `ChatExport_*/`, либо любой каталог, где рядом
   лежат `raw/` и `INDEX.md`.
2. Не нашёл → обычный `init`: создаёт скелет §8, пустой `MANIFEST.json`, заглушки summaries
   и **сразу исключает каталог экспорта из git хост-проекта** — записью в `.git/info/exclude`,
   если репа чужая, либо в `.gitignore`, если своя. Делается до появления первого файла
   с данными, а не после.
3. Нашёл → **режим приёмки**:
   - разбирает найденное, сопоставляет со стандартом;
   - выводит план: что переезжает как есть, что достраивается, какой `fidelity`
     проставлен каждому материалу и по какому признаку, что не распозналось;
   - **ждёт явного подтверждения**;
   - выполняет: копирует содержимое (не перемещает), строит `MANIFEST.json`,
     генерирует `INDEX.md`, прогоняет `verify`;
   - исходный каталог не удаляет — это решение пользователя после проверки.

**Правила определения `fidelity` при приёмке** (в порядке приоритета):

1. Явная пометка в исходном тексте («ДОСЛОВНО», «конспект», «не восстановимо») — приоритет над всем.
2. Файл в `raw/messages/` рядом с машинным экспортом (`result.json`) → `verbatim`.
3. Файл в `summaries/` или с «конспект»/«саммари» в имени → `digest`.
4. Упоминание в тексте без файла на диске → `placeholder`.
5. Не определилось → спросить, не угадывать.

## 11. Правила `verify`

Линтер детерминированный, без участия модели. Каждое правило даёт код и путь.

| Код | Проверка |
|---|---|
| `V01` | для каждого `item` со `status: present` файл по `raw_path` существует |
| `V02` | `sha256` совпадает с фактическим содержимым файла |
| `V03` | каждый файл в `raw/` учтён: он либо `raw_path` какого-то `item`, либо входит в его `derived_paths` |
| `V04` | все относительные ссылки в `INDEX.md` и `summaries/*.md` ведут в существующие пути |
| `V05` | `fidelity != verbatim` ⇒ `fidelity_note` непустой |
| `V06` | `status: missing` ⇒ `raw_path` задан, файла нет; `status: unrecoverable` ⇒ `raw_path: null` и `fidelity: placeholder` |
| `V07` | все обязательные файлы §8 присутствуют |
| `V08` | `INDEX.md` не старше `MANIFEST.json` по mtime (иначе «пересобери») |
| `V09` | каждый `item.redactions[]` ссылается на существующую запись в `redactions` |
| `V10` | `id` уникальны; `date` — валидная дата не из будущего |
| `V11` | нет файлов вне разрешённых зон §8 |
| `V12` | каталог экспорта исключён из git хост-проекта (`.gitignore` или `.git/info/exclude`) |

Ненулевой выход при любой ошибке. Предупреждения (`V08`) отделены от ошибок.

`V12` — защита от главного риска: клиентские данные не должны уехать в чужую репу.
`init` прописывает исключение сам, `verify` следит, что его не отменили.

## 13. Приёмка

Стандарт считается рабочим, когда:

1. `verify` проходит на свежесозданном пустом экспорте;
2. приёмка съедает все три референсных экспорта (§3) без потери содержимого,
   и после неё `verify` проходит на каждом;
3. на корпусе из трёх экспортов встречаются все четыре значения `fidelity`, и
   каждое проставлено обоснованно. Внутри одного экспорта полный набор не
   обязателен: `digest`-записи появляются только там, где конспект хранится как
   материал, а не как текущий слой навигации (см. `SPEC/STANDARD.md` §8);
4. `INDEX.md`, удалённый и пересобранный из `MANIFEST.json`, эквивалентен исходному;
5. `publish` не выпускает ни одного материала с `contour: work`.
