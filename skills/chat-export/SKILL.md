# Chat export по стандарту mnemo

Приём рабочего контекста в архив, на который можно ссылаться: переписка, документы,
скрины, транскрипты созвонов. Итог — каталог, где у каждого материала известны
происхождение и достоверность, а целостность проверяется линтером.

**Нормативный документ — `SPEC/STANDARD.md` в корне плагина.** Он источник истины;
этот файл описывает, как его применять. Расхождение между ними — дефект этого файла.

## Когда применять

- просят сохранить переписку, ТЗ, вложения, скрины, транскрипт;
- передают или принимают проект и нужно зафиксировать состояние;
- уже есть самодельный экспорт и его надо привести к стандарту;
- просят записать проверенный факт, рабочее правило или изъятие.

## Устройство

Работа делится на две части, и смешивать их нельзя.

**Скрипты делают механическое.** Копирование, хеши, распаковка документов, генерация
`INDEX.md`, проверка правил. Всё детерминировано и воспроизводимо.

**Ты делаешь то, что требует суждения.** Определить достоверность, написать пересказ,
отличить правило от факта, решить, что изымать. Это нельзя переложить на скрипт, и
именно ради этого навык существует.

Не пиши `MANIFEST.json` и `INDEX.md` руками. Первый пишется скриптами, второй
генерируется. Ручная правка `INDEX.md` теряется при следующем `sync`.

## Сквозной пример: от нуля до отчёта

Один сюжет целиком. Разделы ниже объясняют каждый шаг подробно — здесь важен
**порядок** и то, что из чего следует.

**Дано:** передают проект. Есть выгрузка рабочего чата, ТЗ в `.docx`, и через
неделю у тебя спросят, всё ли сделано, как хотел заказчик.

**1. Завести архив** — `/mnemo:init`

```
mnemo_manifest.py init --dir _chat-export --slug priyomka --title "Приёмка проекта"
```

Создаёт раскладку, исключает каталог из git и дописывает в `CLAUDE.md` проекта
блок про архив — чтобы следующая сессия узнала о нём на старте, а не искала.
`--slug` входит в каждую ссылку `ctx:priyomka#i004` и потом не меняется.

**2. Внести выгрузку** — `/mnemo:import`

```
mnemo_import.py --export _chat-export --source ~/Downloads/ChatExport_2026-07-21
mnemo_import.py --export _chat-export --source ~/Downloads/ChatExport_2026-07-21 --apply
```

Без `--apply` — только план. Формат опознаёт реестр парсеров; вложения приходят
вместе с сообщениями. Импорт сам скажет, кого из участников нет в реестре людей.

**3. Сказать, кто есть кто** — `/mnemo:people`

```
mnemo_manifest.py people --export _chat-export --add --display "Пётр Иванов" \
  --role client --aliases "Пётр,petr" --telegram petr_ivanov
```

Без этого шага «что говорил заказчик» находит треть, а `--wanted-by` в
требованиях ссылаться не на кого.

**4. Документ, пришедший отдельно** — `/mnemo:add-files`

```
mnemo_manifest.py add-file --export _chat-export --kind attachment \
  --file ~/Downloads/ТЗ.docx --source docx --fidelity verbatim --extract
```

`--extract` достаёт текст и вшитые картинки — иначе содержимое `.docx` в архиве
есть, а найти его нельзя.

**5. Снять с переписки то, ради чего всё делается** — `/mnemo:req`, `/mnemo:ask`

```
mnemo_manifest.py req --export _chat-export --quote "Выгрузка нужна за весь июль" \
  --wanted-by petr-ivanov --based-on "ctx:priyomka#i012" --blocking "без неё не считается отчёт"

mnemo_manifest.py ask --export _chat-export --text "Кто согласует тариф?" \
  --impact "по какой ставке считать корзину — фиксированной или из справочника" \
  --asked-of petr-ivanov --based-on "ctx:priyomka#i014"
```

Все три поля у вопроса **обязательны**, и заполнять их наугад бессмысленно —
разбор ниже говорит, что по каждому проверить.

Дословно и сразу. Пересказ задним числом теряет формулировку, а спор всегда идёт
о формулировке. Когда вопрос ушёл человеку — отметь, иначе спросишь второй раз:

```
mnemo_manifest.py ask --export _chat-export --id q001 --raised-to petr-ivanov \
  --where "чат 04.08"
```

**6. Разложить текстовое по природе** — `/mnemo:rule`, `/mnemo:note`

Правило («с заказчиком общаемся только через начальство») дописывается в
`summaries/conventions.md` с источником. Проверенный факт («регрессия прогнана,
9 падений одинаковые») — в `summaries/findings-log.md` со статусом. Пересказ
переписки — в `<дата>_chat-summary.md`. Три разных файла, и путать их нельзя.

**7. Изъять чужое** — `/mnemo:redact`

```
mnemo_manifest.py redact --export _chat-export --reason pii \
  --description "паспортные данные директора" --scope "сообщение от 12.07" --items i031
```

Описание говорит, **что** изъято, не раскрывая изъятого.

**8. Пересобрать и проверить** — `/mnemo:sync`, `/mnemo:verify`

```
mnemo_render.py --export _chat-export
mnemo_verify.py --export _chat-export
```

Обязательно после каждой мутации. Результат линтера показывай человеку.

**9. Ответить на вопрос, ради которого всё затевалось** — `/mnemo:audit`

```
mnemo_audit.py --export _chat-export
```

Блокирующее сверху, возраст блокировки, `[НЕ СПРАШИВАЛИ]` у того, что ты только
записал, но никому не задал, и отдельно — заявленное против подтверждённого.

**Что чаще всего ломается на этом пути:** пропущенный шаг 3 (потом не связать
слова с людьми), `done` без `--evidence` (это мнение, а не отчёт) и правка
`MANIFEST.json` руками вместо команды.

## Скрипты

`${CLAUDE_PLUGIN_ROOT}/scripts/` — только стандартная библиотека Python 3, ничего
устанавливать не нужно.

| Скрипт | Назначение |
|---|---|
| `mnemo_manifest.py` | `init`, `add-file`, `add-text`, `add-gap`, `redact`, `remove`, `req`, `ask`, `people`, `whois`, `rehash`, `show` |
| `mnemo_import.py` | импорт источника целиком; формат определяется реестром парсеров |
| `mnemo_extract.py` | текст и вшитые картинки из `.docx` / `.xlsx` |
| `mnemo_render.py` | пересборка `INDEX.md` и `summaries/redactions.md` |
| `mnemo_verify.py` | линтер V01–V20 |
| `mnemo_selfcheck.py` | согласованность самого плагина: версии, правила, префиксы |
| `mnemo_audit.py` | сводка «всё ли сделано как хотели» |
| `mnemo_publish.py` | публичный срез: детерминированный отбор по контуру |

У всех есть `--help`. Читай его, а не угадывай флаги.

**После любой мутации:** `mnemo_render.py --export <dir>`, затем
`mnemo_verify.py --export <dir>`. Результат линтера показывай человеку — молча
проглоченная ошибка обесценивает стандарт.

## Достоверность: как определять

Четыре уровня, полная модель — `SPEC/PROVENANCE.md`.

| Уровень | Когда ставить |
|---|---|
| `verbatim` | материал получен механически: выгрузка, приложенный файл, оригинал скрина |
| `reconstructed` | текст дословный, но добыт из вторичного следа (лог сессии, пересланная копия) |
| `digest` | твой или чужой пересказ, конспект, сводная таблица |
| `placeholder` | оригинала нет, есть только описание |

Правила:

1. **Явная пометка в исходнике важнее эвристики.** Написано «конспект» — значит `digest`.
2. **При сомнении бери уровень слабее.** Занизить безопасно, завысить — нет.
3. **Не угадывай.** Не определяется — спроси человека, какой источник.
4. **`digest` никогда не цитируется как чьи-то слова.** Это главное правило всей системы.

Всё, кроме `verbatim`, обязано нести `--note` с объяснением: откуда взято и что при
переносе потерялось.

## Надёжность авторства

Ось, **независимая от достоверности**: текст бывает дословным, а подпись под ним —
не того человека.

| `attribution` | Когда |
|---|---|
| `reliable` | автор точно известен (машинная выгрузка с `forwarded_from`, прямое сообщение) |
| `forwarder-shown` | видно только пересылающего — копипаста из Telegram всегда такая |
| `unknown` | непонятно |

Почему это отдельное поле: в Telegram копипаста подписывает **пересланное**
сообщение тем, кто переслал. На живом рабочем чате так вышло с 16 сообщениями из
21 — все требования заказчика достались бы переславшему их руководителю.

При `forwarder-shown` **запрещено** приписывать материал указанному автору.
Допустимая формулировка: «переслано <кем>, автор не установлен». Повысить
надёжность может только человек, подтвердив авторство из другого источника.

## Кто есть кто

`people` в манифесте связывает разные имена одного человека: отображаемое имя в
мессенджере, логин в git, имя в разговоре. Без этого поиск «что говорил X»
находит треть, а ты не знаешь, кто из участников — твой собеседник.

```
mnemo_manifest.py people --add --display "..." --role self|colleague|management|client|other \
  --aliases "как встречается в источниках" --github ... --telegram ...
mnemo_manifest.py whois "Эрми 🤍"
```

Роль `self` — оператор архива, тот, с кем ты разговариваешь. Она одна.

Импорт сам сообщает, кого нет в реестре. Не выдумывай роли и связи: спроси
человека, кто это и кем приходится. Рабочие порядки («с заказчиком общаемся
только через начальство») — это `conventions.md`, а не роль: у другой команды
они другие.

## Импорт источников

Выгрузка всегда лучше копипасты: она знает настоящего автора и содержит вложения.
Если человек прислал копипасту, а выгрузку сделать можно — скажи об этом.

Повторный импорт той же выгрузки безопасен: ключи принятых сообщений лежат в
манифесте. Поэтому при появлении новой информации правильный путь — **выгрузить
чат заново целиком**, а не нарезать по датам и не доносить копипастой.

### Три источника, и они не взаимозаменяемы

| Источник | Когда | Надёжность авторства |
|---|---|---|
| **выгрузка чата** (`result.json`) | всё, что было **до** появления бота | `reliable` — формат знает автора пересылки |
| **буфер захвата** (каталог от `inbox_export`) | всё, что **после**: добор за день, за утро | разная **внутри одной пачки** |
| **копипаста** | когда ни того, ни другого нет | `forwarder-shown` всегда |

**Буфер захвата** — это бот herald, читающий рабочие группы. Он отдаёт
самодостаточный каталог:

```
bundle/
├── inbox.json        строки сообщений, local_path — относительный путь
└── files/<slug>/…    вложения
```

Импортируется как обычный источник: `mnemo_import.py --source bundle`, потом
`--apply`. Каталог — **один чат**: номера сообщений в разных чатах повторяются,
и смешение молча теряло бы часть; парсер такую пачку отвергает.

Чего в буфере нет по устройству: истории до добавления бота, удалений и правок.
Поэтому он **не заменяет выгрузку**, а дополняет её.

**Надёжность в этом формате разная у разных сообщений** (§4а.5). Определяет её
поле `origin_type`:

| `origin_type` | Что значит | Что попадёт в архив |
|---|---|---|
| нет | написал тот, кто отправил | `reliable` |
| `user` | переслано, автор опознан | `reliable`, автор настоящий, пересылающий отдельно |
| `hidden_user` | автор скрыл себя | `forwarder-shown`, автор **не установлен**, показанное имя рядом |
| `chat` / `channel` | источник — чат или канал | `forwarder-shown`, автор не установлен |

Материал за день получает **слабейшую** надёжность из вошедших в него (§4а.6), а
ненадёжные сообщения помечаются `⚠` прямо в транскрипте (§4а.7). Не «исправляй»
это: понижение — не ошибка, а честный ответ.

Новые форматы добавляются как модуль в `scripts/parsers/` — ядро о них не знает.
Не разбирай незнакомый формат вручную по ходу: либо парсер, либо честный
`add-text` с пониженной достоверностью.

## Требования и вопросы — то, ради чего спрашивают отчёт

Архив хранит не только материал, но и **что от нас хотят** и **чего мы не знаем**.
Полный контракт — `SPEC/STANDARD.md` §6б.

```
mnemo_manifest.py req  --quote "<дословно>" --wanted-by "<кто>" --based-on "ctx:…#iNNN"
mnemo_manifest.py req  --id tNNN --state done --evidence "<чем подтверждено>"
mnemo_manifest.py ask  --text "<вопрос>" --impact "<что меняется от ответа>"
mnemo_manifest.py ask  --id qNNN --raised-to "<кому>" --where "<где спросил>"
mnemo_audit.py                     # ответ: всё ли сделано как хотели
```

Три правила, без которых это не работает:

1. **`done` требует доказательства.** Без него это мнение, а не отчёт.
2. **Отмечай `--raised-to`, когда вопрос ушёл человеку.** Иначе следующая сводка
   поднимет его как новый, и ты спросишь второй раз то, что уже спрашивал.
3. **Заполняй `--blocking`, когда работа правда упирается.** Это ось, по которой
   сводка отделяет существенное от мелочей.

### Заслон на вопросы: три поля, которые надо ПРОВЕРИТЬ, а не предположить

Новый вопрос без `--impact`, `--asked-of` и `--based-on` инструмент **не
заведёт**. Это не формальность: каждое поле — проверка, которую ты обязан
провести до записи. Заполнить их правдоподобным текстом технически можно; это
обман самого себя, и вскроется он через неделю в виде мёртвого списка.

Ниже — что именно проверять по каждому.

#### `--impact` — что изменится в работе от ответа

**Проверка, а не ощущение:** назови **два разных исхода** ответа и для каждого —
что конкретно будет сделано иначе **в репозитории или в конфигурации**.

| Проверил | Годится |
|---|---|
| назвал файл, поле схемы, миграцию, эндпоинт, значение конфига, выбор библиотеки | да |
| «будет понятнее», «важно для проекта», «нужно для качества» | нет |
| оба исхода ведут к одному и тому же коду | нет — это не вопрос |

Разработческая формулировка: **если ты не можешь начать работу, не зная ответа,
или начнёшь и переделаешь — вопрос настоящий.** Если можешь спокойно писать
дальше и ответ ничего не отменит — это любопытство, ему место в разговоре, а не
в архиве.

Пиши в `--impact` **последствие, а не пересказ вопроса**. «Формат артикулов» —
пересказ. «Тип поля в схеме и логика парсера импорта: строка с ведущими нулями
или целое» — последствие.

#### `--asked-of` — кто реально может ответить

**Проверка в три шага, все обязательны:**

1. **Человек есть в реестре** — `whois <имя>`. Нет в реестре: сначала `people`,
   потом вопрос. Иначе ссылка ведёт в никуда, и линтер это отвергнет (`V14`).
2. **Он правда владеет ответом.** Разработчик не отвечает за коммерческие
   условия, заказчик — за выбор библиотеки. Ошибся адресатом — вопрос уйдёт и
   вернётся ни с чем, а в сводке будет числиться заданным.
3. **Ответ не за нами.** Спроси себя: **можем ли мы решить это сами и просто
   сообщить о решении?** Если да — это не вопрос, а решение, которое надо
   принять. Записывай его как требование или в `conventions.md`, не как вопрос.

Отдельно про «не в нашей компетенции»: если ответа нет ни у кого из доступных
людей и решение принимает сторона, до которой мы не дотягиваемся, — вопрос **не
заводится**. Вместо него — требование с `--blocking`, описывающее, что стоит.
Разница практическая: требование адресовано нам и попадёт в отчёт как
незакрытое, а вопрос в пустоту просто копится.

#### `--based-on` — из какого материала вопрос возник

**Проверка: открой этот материал и убедись, что вопрос действительно оттуда.**
Не по памяти, не «кажется, было в переписке».

- `show --id iNNN` или прочитай `raw_path` — в нём должно быть то место, которое
  вопрос породило;
- если материала в архиве нет — сначала внеси его (`add-text`, `add-files`,
  `import`), потом вопрос;
- если породившего материала не существует вовсе, вопрос родился у тебя в
  голове. Иногда это правильный вопрос — тогда сначала заведи `add-gap` или
  запиши факт в `findings-log`, чтобы у него появилось основание.

Ссылка обязана быть `ctx:<slug>#iNNN` — от слага экспорта, не от имени каталога.

#### Перед записью — перепроверить

Инструмент сам покажет похожие записи и откажется писать без явного решения. Но
до этого проверь то, чего он не видит:

1. **Ответ уже может лежать в архиве.** Поищи по `summaries/` и `INDEX.md`
   прежде, чем спрашивать человека. Половина «открытых вопросов» закрывается
   чтением того, что уже принято.
2. **Вопрос мог быть задан и забыт.** `audit` показывает отметки `raised` —
   посмотри, не спрашивали ли это в другой формулировке.
3. **Один вопрос — одна неизвестность.** «Какой формат артикулов и нужен ли
   PDF?» — два вопроса, и ответят на один. Разделяй при записи.

### Что делать с секцией «ПРОТУХЛО»

`audit` выводит отдельно записи без движения дольше недели. Это **не** часть
открытого списка, и относиться к ним надо иначе:

- **вопрос спрошен, ответа нет** — переспроси (`--raised-to` снова, отметки
  накапливаются) либо сними с причиной (`--dropped-reason`). Ждать дальше —
  значит держать в отчёте то, чего не будет;
- **вопрос лежит и никому не задан** — задай сегодня или сними. Двадцать таких
  и есть тот мёртвый список, ради которого заслон появился;
- **требование `done`, но заказчик не принял** — добейся приёмки и поставь
  `verified`, либо честно оставь `done` и покажи в отчёте как непринятое.

Записи в этой секции — **работа на сегодня**, а не фон.

Заводи требование сразу, как только заказчик что-то сказал, — дословно. Пересказ
задним числом теряет формулировку, а спор всегда идёт о формулировке.

**Пачкой — при приёмке.** Из одного ТЗ выходит два десятка требований, и
двадцать вызовов с одинаковыми хвостами — это то, на чём начинают срезать углы:

```
mnemo_manifest.py req --batch trebovaniya.md --wanted-by petr-ivanov          # план
mnemo_manifest.py req --batch trebovaniya.md --wanted-by petr-ivanov --apply  # запись
```

По записи на строку, хвост после `::` — ссылки `based_on` для этой строки.
Устроено как импорт: сначала план, потом `--apply`; совпадающие с уже
заведёнными пропускаются, поэтому файл можно дополнять и прогонять снова.

Отношения между конкретными записями пакету недоступны намеренно:
`--supersedes` у `req` и отметки `--raised-to` / `--answered-by` у `ask` он
отвергает. Один такой флаг на двадцать записей был бы неправдой в девятнадцати.

## Что куда попадает

Три текстовых артефакта легко перепутать. Разница по природе содержимого:

| Артефакт | Что туда | Признак |
|---|---|---|
| `conventions.md` | **правила**: как работаем, что нельзя трогать, куда писать журнал | действует и завтра; обязателен источник — кто сказал и когда |
| `findings-log.md` | **факты**: что проверено, что воспроизвелось, что выяснилось | относится к моменту; имеет статус жизненного цикла |
| `*-summary.md` | **содержание**: о чём переписка, какие решения в документах | пересказ материала, а не вывод из него |

Проверка: «не пушим в master без согласования» — правило. «Регрессия прогнана,
9 падений на всех ветках одинаковые» — факт. «Клиент выбрал вариант 3» — содержание
документа.

### Жизненный цикл записи в `findings-log.md`

Каждая запись обязана нести статус:

- `open` — зафиксировано, никуда не отправлено;
- `distributed` — донесено; **обязательно куда и чем** (issue, коммит, дейлик);
- `dropped` — снято; обязательна причина.

Между «проверил» и «донёс до места, где это нужно» проходят часы и несколько
контекстов. Без статуса эта дистанция теряется, и работа делается дважды.

## Пересказы

`attachments-summary.md` — рабочий документ, а не аннотация. Из него должно быть
понятно, **что решено и на что сверяться**, без открытия оригиналов. Помечай явные
решения заказчика так, чтобы их было видно глазом.

`<дата>_chat-summary.md` — о чём договорились, кто что взял, что осталось открытым.

Оба пересказа — `digest` по природе. Ссылайся из них на RAW, чтобы можно было
проверить первоисточник.

## Изъятия

Изымай персональные данные, чужие проекты, протёкшее служебное, клиентскую тайну.

`--description` говорит, **что** изъято, но не раскрывает изъятое. Правильно:
«паспортные данные директора». Неправильно: сами данные. Описание, раскрывающее
содержимое, отменяет смысл изъятия.

Обратимое изъятие обязано указать `--vault-ref` — путь **вне экспорта**. Изъятое
и экспорт не хранятся вместе.

## Приёмка существующего экспорта

Подробный порядок — `references/adoption.md`. Коротко: разобрать, показать план,
дождаться подтверждения, скопировать (не переместить), собрать манифест, проверить.

Никогда не удаляй исходный каталог сам. Это решение человека после проверки.

## Снятие записи

Материал заведён по ошибке или оказался дублем — снимай командой, **никогда не
правя `MANIFEST.json` руками**:

```
mnemo_manifest.py remove --export <dir> --id iNNN --reason "<почему>" [--confirm]
```

Правка манифеста руками обходит проверку контракта в момент записи — то самое,
ради чего манифест пишется только инструментом. Если команды для чего-то не
хватает, это дефект инструмента: скажи человеку, а не лезь в файл.

Снятый идентификатор **не выдаётся повторно**: ссылку на него могли записать в
issue или дейлик, и после переиспользования она указывала бы на другой материал.
Файл уходит в корзину, откуда возвращается через `trash-restore`.

## Столкновения

Правила целиком — `SPEC/STANDARD.md` §8б. Что важно помнить:

- **Ничего не пишется поверх существующего файла**, и обойти это нечем: флага
  «всё равно перезаписать» нет намеренно. Нужна вторая копия — дай ей другое имя:
  `--label` у `add-text`, `--name` у `add-file`.
- **Повтор узнаётся по двум ключам** — номеру сообщения и отпечатку текста.
  Поэтому смешивать выгрузку и копипасту безопасно: один и тот же текст дважды
  не зайдёт. Короткие реплики («ок») из этого исключены и могут повториться.
- **Ручные `add-text` и `add-file` в дедупликацию не входят** — они кладут блоб,
  а не поток сообщений. Для материала из чата предпочитай `import`.

## Границы

- **RAW не редактируется.** Ошибка в исходнике остаётся в исходнике; пояснение
  идёт в `summaries/`.
- **Пропуск фиксируется, а не замалчивается.** Нет оригинала — заводи `add-gap`.
  Тихо пропустить материал хуже, чем показать дыру.
- **Ответ без источника не выдаётся.** Ссылка на `item.id` и `raw_path` плюс уровень
  достоверности — обязательны.
- **Экспорт исключается из git до появления в нём данных.** `init` делает это сам;
  если линтер ругается на V12 — это не косметика, а риск утечки в чужой репозиторий.
