# Backlog

Идеи, к которым стоит вернуться. Всё перечисленное ложится **поверх** стандарта
и не требует его переписывания — при условии, что контракт `item` заложен верно.

Порядок внутри разделов — не приоритет.

---

## Поиск

- **B1. Векторный индекс.** Чанкинг → эмбеддинги → локальный векторный стор
  (sqlite-vec или FAISS). Метаданные — рядом в SQLite. Обязательное условие:
  выдача несёт `item.id`, `raw_path` и `fidelity`, иначе теряется цитируемость.
- **B2. Гибридный поиск.** Вектор + BM25. Открытый вопрос: нужен ли сразу или
  полнотекстового поиска хватает на архивах такого размера.
- **B3. Реранкер.** После B1–B2, если качество выдачи окажется проблемой.
- **B4. Взвешивание по свежести.** Свежий материал обычно релевантнее — но не
  всегда: acceptance от заказчика не устаревает.

## Доступ

- **B5. MCP-сервер** поверх поиска: инструменты `search(query, filters)` и
  `get(item_id)`. Ассистент запрашивает архив как инструмент. Именно ради этого
  сценария выбрана AGPL.
- **B6. Централизованный стор.** Сейчас экспорт живёт рядом с проектом. Когда
  появится поиск, захочется искать сразу по всем — нужна опция «где стор» с
  сохранением текущего поведения по умолчанию.
- **B7. Telegram-адаптер.** Спросить архив с телефона, скинуть боту файл на приём.

## Приём материала

- **B8. Расшифровка голосовых.** Локальная модель. Результат — `digest` или
  `reconstructed`, но **не** `verbatim`: распознавание ошибается, и достоверность
  обязана это отражать.
- ~~**B9. Парсер Telegram Desktop.**~~ ✅ JSON сделан (`parsers/tg_json.py`) плюс
  копипаста (`parsers/tg_paste.py`). HTML-выгрузка — осталась.
- ~~**B10. Инкрементальный приём.**~~ ✅ журнал `imports` в манифесте: повторная
  выгрузка того же чата приносит только новое.
- **B11. Дедупликация.** Один материал, пришедший из двух источников. Открытый
  вопрос: склеивать в одну запись или хранить обе со ссылкой друг на друга.
- **B18. HTML-выгрузка Telegram** — второй формат, который отдаёт Desktop.
- **B19. Расшифровка голосовых** — теперь в архив попадают реальные `.ogg`, и
  им нужен текст; результат обязан быть `reconstructed`, не `verbatim`.
- **B12. PDF и iWork.** Сейчас не разбираются стандартной библиотекой. Либо
  опциональная зависимость, либо внешний конвертер по требованию — но без
  превращения ноль-зависимостей в фикцию.

## Приватность

- **B13. Стыковка с pdn-depersonalizer.** Автоматическая деперсонализация на приёме:
  найденные ПДН уходят в `redactions` с `reversible: true`, маппинг — в хранилище
  вне экспорта. Готовый проект уже есть, нужна только точка вызова.
- **B14. Шифрованный синк.** Экспорт между машинами через git, в репозиторий
  уезжает только зашифрованный бандл (`age`/`gpg`). Открытый вопрос: гранулярность
  бандла и стратегия при конфликте (скорее replace, чем merge).

## Смежное

- **B15. Дейлики.** Коннектор к ежедневным логам, связка «дейлик ↔ контекст».
  Технический devlog для поиска ценнее, чем сводка для начальства, — при
  индексации это надо различать.
- **B16. Связь между экспортами.** Один проект, несколько экспортов в разное время.
  Сейчас они друг о друге не знают.
- **B17. Экспорт в другие форматы.** Obsidian-совместимый вывод — самый вероятный
  запрос, если стандартом начнёт пользоваться кто-то ещё.
